# SableOS Panther device integration

Bounded Google Pixel 7 (`panther`) integration and physical qualification boundary for SableOS.

This repository is a **device adapter and runtime qualification owner**. It must not contain forked copies of common Sable applications or common product semantics merely because Panther is the current PRIMARY reference target.

## Current reference role

Panther remains the primary Android 17 / GrapheneOS-derived product-development/security/runtime target.

Common Sable behavior belongs in common application/platform repositories. Common product selection belongs in `vendor_sable`. This repository owns only Panther-specific adaptation and Panther-specific/runtime evidence.

## Current program state

R7 remains the daily-driver/runtime requirements baseline, but the forward source/integration train is now R8.

```text
R7
  daily-driver requirements + Panther product/build evidence baseline
  remaining unexecuted runtime cases stay explicit
        |
        v
R8 Process A
  standalone app qualification outside Panther image build
        |
        v
R8 integration freeze
        |
        v
R8 Process B on trusted builder
  product wiring + Panther image
        |
        v
Panther Device1 R8 integration/regression campaign
```

R8 does **not** make `device_sable_panther` an application compiler or application source repository.

## R7 requirement baseline

The historical/ongoing runtime matrix remains:

- [`docs/R7_DAILY_DRIVER_VALIDATION.md`](docs/R7_DAILY_DRIVER_VALIDATION.md)

It covers calls, contacts, SMS/MMS, Wi-Fi, cellular data, Internet/browser, notifications, Settings, camera/photos, files, clock/alarm, Calculator baseline and Sable Start access.

Starting R8 source work does not turn unexecuted R7 cases into PASS. The matrix remains a regression/acceptance source for the next accepted Panther image where applicable.

## Product/build evidence learned from R7

Panther build forensics reinforced the claim ladder:

```text
source/prebuilt
 -> graph edge
 -> product selection
 -> PRODUCT_OUT
 -> target-files/image
 -> runtime
```

Recent firmware packaging evidence established direct standalone vendor-prebuilt/product/target-files provenance for ABL, aggregate bootloader and radio artifacts. The standalone ABL artifact is not generated by unpacking `bootloader.img`; the aggregate bootloader independently contains the same ABL payload.

This is build/product evidence, not daily-driver runtime evidence.

## R8 Panther campaign

After the R8 standalone application set is frozen and the product import/wiring mechanism is proven, the Panther campaign should validate the exact resulting image for:

- installed package/component identity;
- launcher visibility/launch;
- R8-A Follow system/Light/Dark/accent behavior;
- Calculator/Convert/Games representative interaction/accessibility;
- one Sable Reader product with the accepted EPUB/TXT/share/TTS/OCR capability set;
- Reader network/model-download policy boundary;
- Sable Media local-vs-network permission/storage behavior;
- cross-app/system intent handling;
- permissions/AppOps/roles/defaults as applicable;
- required R7 daily-driver regressions;
- reboot persistence only where reboot is explicitly authorized.

## Trusted builder transition

The next full R8 Panther image is planned on the migrated `ai-g732` trusted build environment, not as another broad image build on the old ThinkPad solely because historical OUT trees are present.

This device repository does not own that host migration, but Panther acceptance must bind to the exact resulting build/image hashes and source/artifact freeze.
